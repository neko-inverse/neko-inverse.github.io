<p>以下为Linux操作系统(CentOS)，连接虚拟机的终端软件可以使用<strong>MobaXterm</strong></p>
<h4>基础命令：</h4>
<p><strong>PS:不知道命令具体怎么写，有什么参数的，可以后面接上<code>--help</code>查看(适用于所有命令)</strong></p>
<ul>
<li>
<p>从镜像仓库拉取镜像到本地</p>
<pre><code class="language-docker">docker pull 镜像名</code></pre>
</li>
<li>
<p>本地上传镜像到镜像仓库</p>
<pre><code class="language-docker">docker push</code></pre>
</li>
<li>
<p>查看所有本地镜像</p>
<pre><code class="language-docker">docker images</code></pre>
</li>
<li>
<p>删除镜像</p>
<pre><code class="language-docker">docker rmi 镜像名:版本号</code></pre>
</li>
<li>
<p>自定义镜像：dockerfile文件使用如下命令构建</p>
<pre><code class="language-docker">docker build</code></pre>
</li>
<li>
<p>将镜像保存到本地变成压缩文件</p>
<pre><code class="language-docker">docker save -o 文件名.后缀 镜像名:版本号</code></pre>
</li>
<li>
<p>将压缩文件加载成镜像</p>
<pre><code class="language-docker">docker load</code></pre>
</li>
<li>
<p>创建并运行容器(运行后显示容器ID)</p>
<pre><code class="language-docker">docker run -d(后台运行) --name(容器名) -p(端口映射) 80:80(宿主机:容器内) -e(环境变量) 镜像名(不加版本默认最新)</code></pre>
</li>
<li>
<p>停止容器内的进程</p>
<pre><code class="language-docker">docker stop 容器名</code></pre>
</li>
<li>
<p>启动容器内停止的进程</p>
<pre><code class="language-docker">docker start</code></pre>
</li>
<li>
<p>查看当前容器的运行状态</p>
<pre><code class="language-docker">docker ps</code></pre>
</li>
<li>
<p>删除容器</p>
<pre><code class="language-docker">docker rm [-f(强制删除，运行中的也能删)]</code></pre>
</li>
<li>
<p>查看容器运行日志</p>
<pre><code class="language-docker">docker logs</code></pre>
</li>
<li>
<p>进入容器内部(进入后<code>exit</code>可以退出来)</p>
<pre><code class="language-docker">docker exec -it(添加一个可输入的终端) 容器名 bash(命令行)</code></pre>
</li>
<li>
<p>进入root目录下的.bashrc文件设置命令别名</p>
<pre><code class="language-docker">vi ~/.bashrc</code></pre>
<pre><code class="language-docker">source ~/.bashrc  (使更改后的生效)</code></pre>
</li>
<li>
<p>查看容器详情</p>
<pre><code class="language-docker">docker inspect</code></pre>
</li>
</ul>
<h4>数据卷</h4>
<p>数据卷(volume)是一个虚拟目录，是容器内目录与宿主机目录之间映射的桥梁。映射示例参考下图：</p>
<p><img src="https://tuchuang.shifengzhi.top/picture/image-20240402185058306.png" alt="image-20240402185058306" /></p>
<p><strong>数据卷常见命令：</strong></p>
<ul>
<li>
<p>创建数据卷</p>
<pre><code class="language-docker">docker volume create</code></pre>
</li>
<li>
<p>查看所有数据卷</p>
<pre><code class="language-docker">docker volume ls</code></pre>
</li>
<li>
<p>删除指定数据卷</p>
<pre><code class="language-docker">docker volume rm</code></pre>
</li>
<li>
<p>查看某个数据卷的详情</p>
<pre><code class="language-docker">docker volume inspect</code></pre>
</li>
<li>
<p>清除所有未使用的数据卷</p>
<pre><code class="language-docker">docker volume prune</code></pre>
</li>
<li>
<p>数据卷只能在创建容器时挂载，已经存在的容器没创建数据卷的，会默认创建一个匿名数据卷(名字是字母数字随机生成的)，</p>
<p>在执行<code>docker run</code>命令时，使用<code>-v 数据卷:容器内目录</code>可以完成数据卷挂载，</p>
<p>创建容器时，如果挂载了数据卷且数据卷不存在，会自动创建数据卷，示例如下：</p>
<pre><code class="language-docker">docker run -d --name nginx -p 80:80 -v html:/user/share/nginx/html(镜像仓库里查的) nginx</code></pre>
</li>
<li>
<p>要打开宿主机文件操作数据卷时显示没有权限的话，需要切换到lib目录下 然后输入 <code>chmod 777 docker</code>  就可以有docker文件夹访问权限</p>
</li>
<li>
<p>本地目录挂载：与数据卷挂载基本相同，也是在执行<code>docker run</code>命令时，使用<code>-v 本地目录:容器内目录</code>可以完成本地目录挂载，</p>
<p>注意：本地目录必须以 “/” 或 “./” 开头，如果直接以名称开头，会被识别为数据卷而非本地目录，示例代码如下：</p>
<p>本地目录要事先创建好，容器内目录去镜像仓库里查</p>
</li>
</ul>

<h4>自定义镜像</h4>
<p>先简单了解一下镜像的结构：一个完整的镜像由多个<strong>层(Layer)</strong>组成，像多张纸叠在一起组成书那样，每一层有其负责的功能，添加安装包、依赖、配置等，每次操作都会形成新的一层。多个镜像中会有相似或完全一致的层，称为<strong>基础镜像(BaseImage)</strong>，如应用依赖的系统函数库、环境、配置、文件等，方便在构建时直接复用。此外，还有<strong>入口(Entrypoint)</strong>，它是镜像运行入口，一般是程序启动的脚本和参数。</p>
<p><strong>Dockerfile常见命令：</strong></p>
<p>Dockerfile就是一个文本文件，其中包含一个个的指令(Instruction)，用指令来说明要执行什么操作来构建镜像。将
来Docker可以根据Dockerfile帮我们构建镜像。常见指令如下:</p>
<ul>
<li>
<p>FROM：指定基础镜像，示例：</p>
<pre><code class="language-dockerfile">FROM centos:7</code></pre>
</li>
<li>
<p>ENV：设置环境变量，示例：</p>
<pre><code class="language-dockerfile">ENV key value</code></pre>
</li>
<li>
<p>COPY：拷贝本地文件到镜像的指定目录，示例：</p>
<pre><code class="language-dockerfile">COPY ./jre11.tar.gz /tmp</code></pre>
</li>
<li>
<p>RUN：执行Linux的shell命令，一般是安装过程的命令，示例：</p>
<pre><code class="language-dockerfile">RUN tar -zxvf /tmp/jre11.tar.gz && EXPORTS path=/tmp/jre11:$path</code></pre>
</li>
<li>
<p>EXPOSE：指定容器运行时监听的端口，是给镜像使用者看的，示例：</p>
<pre><code class="language-dockerfile">EXPOSE 8080</code></pre>
</li>
<li>
<p>ENTRYPOINT：镜像中应用的启动命令，容器运行时调用，示例：</p>
<pre><code class="language-dockerfile">ENTRYPOINT java -jar xx.jar</code></pre>
</li>
<li>
<p>构建镜像：</p>
<pre><code class="language-dockerfile">docker build -t myImage:1.0 .(指当前目录)</code></pre>
<p>-t：给镜像起名，repository:tag 格式，tag默认latest</p>
</li>
</ul>

<h4>网络</h4>

<p><strong>网络相关常见命令：</strong></p>

</li>
<li>

<pre><code class="language-docker">docker network rm</code></pre>
</li>
<li>
<p>清除未使用的网络</p>
<pre><code class="language-docker">docker network prune</code></pre>
</li>

<pre><code class="language-docker">docker network connect</code></pre>

</li>

<pre><code class="language-docker">docker network inspect</code></pre>

<h4>DockerCompose</h4>
<p>Docker Compose通过一个单独的docker-compose.yml模板文件(YAML格式)来定义一组相关联的应用容器，帮
助我们实现多个相互关联的Docker容器的快速部署，其格式与<code>docker run</code>十分相似，如下：</p>
<p><img src="https://tuchuang.shifengzhi.top/picture/image-20240404181336970.png" alt="image-20240404181336970" /></p>
<p><strong>docker compose 命令格式：<code>docker compose [OPTIONS] [COMMAND]</code></strong></p>
<p><strong>Options：</strong></p>
<ul>
<li>-f：指定compose文件的路径和名称</li>
<li>-p：指定project名称</li>
</ul>
<p><strong>Commands：</strong></p>
<ul>
<li>up：创建并启动所有service容器</li>
<li>down：停止并移除所有容器、网络</li>
<li>ps：列出所有启动的容器</li>
<li>logs：查看指定容器的日志</li>
<li>stop：停止容器</li>
<li>start：启动容器</li>
<li>restart：重启容器</li>
<li>top：查看运行的进程</li>
<li>exec：在指定的运行中容器中执行命令</li>
</ul>
