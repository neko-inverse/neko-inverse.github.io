<h2>Round One</h2>
<h4>1、简单说一下js中的数据类型</h4>
<ul>
<li>
<p>答：</p>
<p><strong>基本数据类型</strong></p>
<ul>
<li><strong>String:</strong> 字符串，用单引号或双引号包裹</li>
<li><strong>Number:</strong> 数字，包括整数和小数，也包括特殊的数值, 如 <code>Infinity</code>, <code>-Infinity</code> 和 <code>NaN</code></li>
<li><strong>Boolean:</strong> 布尔值，只有 <code>true</code> 或 <code>false</code></li>
<li><strong>Null:</strong> 空值</li>
<li><strong>Undefined:</strong> 未定义的值</li>
</ul>
<p><strong>引用数据类型</strong></p>
<ul>
<li><strong>Array:</strong> 存储有序元素的集合</li>
<li><strong>Object:</strong> 存储键值对的集合</li>
<li><strong>Date:</strong> 表示日期和时间的对象</li>
<li><strong>RegExp:</strong> 表示正则表达式的对象</li>
<li><strong>Function:</strong> 存储代码块的对象</li>
</ul>
<p><strong>ES6 新增数据类型</strong></p>
<ul>
<li><strong>Symbol:</strong> 唯一且不可变的值</li>
<li><strong>BigInt:</strong> 超过 Number 范围的大整数</li>
<li><strong>Map:</strong> 存储键值对的集合，键可以是任何数据类型</li>
<li><strong>Set:</strong> 存储唯一值的集合</li>
<li><strong>WeakMap:</strong> 存储键值对的集合，键是弱引用，不会阻止垃圾回收</li>
<li><strong>WeakSet:</strong> 存储唯一值的集合，值是弱引用，不会阻止垃圾回收</li>
</ul>
</li>
</ul>
<h4>2、什么是闭包</h4>
<ul>
<li>
<p>答：</p>
<p>闭包(Closure)指的是一个函数能够访问并操作它所定义时所在的外部函数作用域中的变量,即使外部函数已经执行完毕返回了。</p>
<p>闭包的特点:</p>
<ol>
<li><strong>函数嵌套</strong>: 闭包必定是一个内部函数,它是在一个外部函数中定义的。</li>
<li><strong>外部函数的变量访问</strong>: 内部函数可以访问并操作外部函数中的变量,即使外部函数已经执行完毕。</li>
<li><strong>延长外部函数变量的生命周期</strong>: 由于内部函数可以访问外部函数的变量,所以外部函数的变量不会随着外部函数的执行而被销毁,而是会一直存在于内存中,直到内部函数被销毁。</li>
</ol>
<p>闭包的主要用途包括:</p>
<ol>
<li><strong>数据封装和私有变量</strong>: 利用闭包可以创建私有变量和方法,实现数据的封装和隐藏。</li>
<li><strong>函数柯里化</strong>: 利用闭包可以实现函数的柯里化,从而实现函数的部分求值。</li>
<li><strong>事件处理和回调函数</strong>: 利用闭包可以在回调函数中访问外部环境的变量。</li>
<li><strong>内存管理</strong>: 由于闭包会导致原有的作用域链不被释放,因此需要注意避免内存泄漏的问题。</li>
</ol>
</li>
</ul>
<h4>3、简述作用域和作用域链</h4>
<ul>
<li>答：
<ol>
<li><strong>作用域(Scope)</strong>:
<ul>
<li>作用域是程序中变量和函数的可见性和生命周期。</li>
<li>作用域分为全局作用域和局部作用域(函数作用域、块级作用域)。</li>
<li>变量在声明时就确定了它的作用域,作用域决定了变量的可见性。</li>
<li>作用域遵循就近原则,即先在当前作用域中查找变量,如果没有找到则向上级作用域查找。</li>
</ul></li>
<li><strong>作用域链(Scope Chain)</strong>:
<ul>
<li>作用域链是一个由所有父级作用域组成的链条。</li>
<li>当在一个作用域中访问一个变量时,JavaScript 引擎会沿着作用域链向上级作用域查找,直到找到该变量或者到达全局作用域。</li>
<li>作用域链的方向是从内向外,从局部到全局。</li>
<li>作用域链决定了标识符的解析顺序,保证了程序的有序性和数据的安全性。</li>
</ul></li>
</ol></li>
</ul>
<h4>4、简述CSS的重排和重绘</h4>
<ul>
<li>
<p>答：</p>
<p><strong>CSS 重排</strong></p>
<ul>
<li>当 DOM 结构发生变化时触发。</li>
<li>浏览器必须重新计算元素的几何属性（位置、大小、边距等）。</li>
<li>这是个耗时的过程，会对页面性能产生负面影响。</li>
</ul>
<p><strong>CSS 重绘</strong></p>
<ul>
<li>当元素的外观发生变化（例如颜色、背景、文本）时触发。</li>
<li>浏览器必须重新绘制受影响的像素。</li>
<li>比重排快，但仍然会影响性能。</li>
</ul>
<p><strong>重排和重绘之间的区别</strong></p>
<ul>
<li><strong>触发器：</strong>重排由 DOM 结构变化触发，而重绘由元素外观变化触发。</li>
<li><strong>影响：</strong>重排需要重新计算元素几何属性，而重绘仅重新绘制受影响的像素。</li>
<li><strong>性能影响：</strong>重排比重绘更耗时，对页面性能影响更大。</li>
</ul>
<p><strong>优化重排和重绘</strong></p>
<ul>
<li>避免在循环中频繁修改 DOM。</li>
<li>使用 CSS 类和转换而不是内联样式。</li>
<li>减少元素层级结构。</li>
<li>使用 GPU 加速，例如 CSS <code>translate</code> 和 <code>transform</code>。</li>
<li>使用 CSS <code>will-change</code> 属性通知浏览器即将发生的重排或重绘。</li>
</ul>
</li>
</ul>
<h4>5、<code>for...in</code>和<code>for...of</code>的区别</h4>
<ul>
<li>
<p>答：</p>
<ol>
<li><strong>遍历对象与遍历数组</strong>:
<ul>
<li><code>for...in</code> 循环用于遍历对象的可枚举属性,包括从原型继承的属性。</li>
<li><code>for...of</code> 循环用于遍历可迭代对象(如数组、字符串、NodeList 等),它会遍历对象的元素值。</li>
</ul></li>
<li><strong>遍历顺序</strong>:
<ul>
<li><code>for...in</code> 循环的遍历顺序是不确定的,因为它会遍历对象的所有可枚举属性,包括从原型继承的属性。</li>
<li><code>for...of</code> 循环会按照数据结构的自然顺序进行遍历,对于数组来说就是索引顺序。</li>
</ul></li>
<li><strong>遍历对象属性</strong>:
<ul>
<li><code>for...in</code> 循环可以遍历对象的所有可枚举属性,包括从原型继承的属性。</li>
<li><code>for...of</code> 循环无法直接遍历对象的属性,因为对象不是可迭代的。如果需要遍历对象的属性,可以使用 <code>Object.keys()</code>, <code>Object.values()</code> 或 <code>Object.entries()</code> 配合 <code>for...of</code> 循环使用。</li>
</ul></li>
<li><strong>遍历性能</strong>:
<ul>
<li>一般来说,<code>for...of</code> 循环的性能要优于 <code>for...in</code> 循环,因为 <code>for...in</code> 循环需要检查原型链上的属性,而 <code>for...of</code> 循环只需要遍历可迭代对象的元素。</li>
</ul></li>
</ol>
<p>总的来说,<code>for...in</code> 更适合遍历对象属性,而 <code>for...of</code> 更适合遍历数组或其他可迭代对象。</p>
</li>
</ul>
<h4>6、<code>for item in 对象</code>遍历时，item是什么？</h4>
<ul>
<li>
<p>答：</p>
<p><code>for...in</code> 循环遍历对象时,<code>item</code> 变量表示的是对象的<strong>键(key)</strong>,而不是值(value)。</p>
</li>
</ul>
<h4>7、<code>v-if</code>和<code>v-show</code>的区别？哪个性能更好？</h4>
<ul>
<li>
<p>答：</p>
<ol>
<li><strong>渲染方式</strong>:
<ul>
<li><code>v-if</code>: 当条件为 false 时,元素不会被渲染到 DOM 中。它会根据条件动态地创建或销毁元素。</li>
<li><code>v-show</code>: 当条件为 false 时,元素的 <code>display</code> 属性会被设置为 <code>none</code>。元素仍然存在于 DOM 中,只是被隐藏了。</li>
</ul></li>
<li><strong>初始渲染性能</strong>:
<ul>
<li><code>v-if</code>: 只有当条件为 true 时,元素才会被渲染。这意味着初始渲染时,<code>v-if</code> 会更快一些。</li>
<li><code>v-show</code>: 元素始终会被渲染到 DOM 中,只是通过 CSS 属性进行隐藏。这意味着初始渲染时,<code>v-show</code> 会更慢一些。</li>
</ul></li>
<li><strong>切换性能</strong>:
<ul>
<li><code>v-if</code>: 每次条件变化时,都会销毁和创建元素。对于频繁切换的场景,<code>v-if</code> 会比 <code>v-show</code> 慢。</li>
<li><code>v-show</code>: 元素只需要通过修改 CSS 属性来切换可见性,这通常比销毁和创建元素快得多。对于频繁切换的场景,<code>v-show</code> 会更快。</li>
</ul></li>
<li><strong>生命周期</strong>:
<ul>
<li><code>v-if</code>: 当条件为 false 时,元素及其子组件的生命周期钩子都不会被触发。</li>
<li><code>v-show</code>: 元素及其子组件的生命周期钩子会一直被触发,无论条件是否满足。</li>
</ul></li>
</ol>
<p>总的来说:</p>
<ul>
<li>如果需要在运行时很少改变条件的场景中,使用 <code>v-if</code> 会更合适,因为它可以确保条件块内的事件监听器和子组件适当地被销毁和重建。</li>
<li>如果需要频繁切换条件的场景中,使用 <code>v-show</code> 会更合适,因为它不会销毁和重建元素,性能会更好。</li>
</ul>
</li>
</ul>
<h4>8、简单说一下快速排序的过程</h4>
<ul>
<li>
<p>答：</p>
<ol>
<li>从数列中挑出一个元素作为基准(pivot)。</li>
<li>将所有比基准小的元素放在基准左边,所有比基准大的元素放在基准右边。这个过程称为分区(partition)操作。</li>
<li>递归地(recursive)把左右两个小问题排序。</li>
</ol>
<p>拓展：</p>
<pre><code class="language-javascript">function quickSort(arr) {
if (arr.length <= 1) {
  return arr;
}

const pivotIndex = Math.floor(arr.length / 2);
const pivot = arr.splice(pivotIndex, 1)[0];
const left = [];
const right = [];

for (let i = 0; i < arr.length; i++) {
  if (arr[i] < pivot) {
    left.push(arr[i]);
  } else {
    right.push(arr[i]);
  }
}

return quickSort(left).concat([pivot], quickSort(right));
}

// 使用示例
const unsortedArray = [5, 2, 9, 1, 7, 3, 8, 4, 6];
const sortedArray = quickSort(unsortedArray);
console.log(sortedArray); // 输出: [1, 2, 3, 4, 5, 6, 7, 8, 9]</code></pre>
<p>这个实现遵循了快速排序的基本步骤:</p>
<ol>
<li>如果数组长度小于或等于 1,直接返回该数组。</li>
<li>选择数组中间的元素作为基准点(pivot)。</li>
<li>将数组分成两部分:小于基准点的元素放在左边数组,大于或等于基准点的元素放在右边数组。</li>
<li>递归地对左右两个子数组进行快速排序。</li>
<li>最后将左右两个排好序的子数组合并起来,即得到排好序的数组。</li>
</ol>
<p>时间复杂度为 O(n log n),是一种非常高效的排序算法。</p>
</li>
</ul>
