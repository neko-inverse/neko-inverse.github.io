> **一句话：** 您只和 Mac 上的 Claude 说话。定时班次、按钮点击、群消息都先进 AWS 的 SQS 队列，EC2 执行机从队列取任务去干，不够就加机器。Mac 平时不干活，执行机全挂了才顶上。

## 1. 总体架构

![总体架构：Mac 主控、SQS 队列、EC2 执行机和共用记录](/uploads/2026/11/sqs-architecture/架构总图.png)

## 2. 各部分干什么

| 部分 | 干什么 | 和现在比 |
|---|---|---|
| **Mac 主控** | 跟您说话、开发上线、派临时任务、看所有执行机。所有活都会干，平时不干；HD 找同款要家里网络，一直在 Mac 上干 | 现在什么都在 Mac 上跑 |
| **EC2 执行机** | 从队列取任务去干。一台够用就一台，不够就加，加机器不改代码 | 现在只当备用机 |
| **SQS 队列** | 存待办任务。取走没办完会重新出现；失败 3 次进死信队列并报警 | 新加 |
| **AWS 定时** | 到点把班次放进队列，不经过 Mac | 现在靠 Mac 的定时 |
| **Lambda** | 收飞书按钮点击和群消息，3 秒内回「已收到」，放进队列 | 现在靠 Mac 一直连着飞书 |
| **DynamoDB** | 共用数据库：防重复记号、锁、台账、拍板、额度、每班状态 | 现在在 Mac 硬盘上 |
| **S3** | 共用文件：日志、证据、面单 PDF，保留 30 天 | 现在在 Mac 硬盘上 |
| **飞书多维表、GitHub** | 业务数据和代码 | 照旧 |

## 3. 一件事怎么走

![两个例子：班次到点、点卡片按钮](/uploads/2026/11/sqs-architecture/一件事怎么走.png)

- **班次到点：** AWS 定时把「某店早班」放进队列 → 执行机取走 → 在 DynamoDB 抢同店锁、查防重复记号 → 跑班次 → 写结果和班次状态 → 删掉任务。看门狗和 17:30 卡片从 DynamoDB 读。
- **点卡片按钮：** 飞书把点击发给 Lambda → Lambda 3 秒内回「已收到」并放进队列 → 执行机取走，照您点的办。
- 任务放了 10 分钟没人取，Mac 取走顶上。

## 4. 出了问题会怎样

| 情况 | 会怎样 |
|---|---|
| Mac 关机、重启、断网 | 班次照常在 EC2 跑，按钮点击照收；只是您暂时找不到我 |
| EC2 挂了 | 任务留在队列里，放了 10 分钟没人取，Mac 取走顶上 |
| 一单办失败 | 这单回到队列再试；失败 3 次进死信队列、报警，别的单照常办 |
| 两台机器抢同一单 | DynamoDB「这条不存在才写」只让一台写成，另一台不买 |
| 接口限流（Lowe's、飞书） | 所有机器共用一个限速计数，加机器不会把接口打爆 |

## 5. 为什么这样选

- **记录放 DynamoDB、不放飞书多维表：** 多维表没有「不存在才写」，两台同时查都是空就会都去买；它还限流。
- **不用 AWS 共享硬盘：** 只能在 AWS 内网挂，家里的 Mac 挂不上，就没法顶班。
- **AI 班次不搬进 Lambda：** Lambda 一次最长 15 分钟，班次一跑几十分钟到几小时，还要技能和浏览器。
- **不多开个人 Claude 账号叠额度：** 订阅额度按个人正常使用算；业务变多以后换企业版或 API。

## 6. 分四步做（约 15–20 班开发）

| 步 | 做什么 | 做完是什么样 | 工作量 |
|---|---|---|---|
| 1 | 防重复记号、锁、台账等搬到 DynamoDB，日志到 S3；先两边同时写对照一天 | 还是 Mac 在干，但记录不在本机硬盘上了 | 5–6 班 |
| 2 | 按钮点击、群消息改由 Lambda 收、放进队列 | Mac 重启那一阵点的卡片不丢 | 2–3 班 |
| 3 | 定时改由 AWS 派进队列，运行器改成从队列取；漏跑按班报警 | Mac 关机，班次在队列里等，回来接着干 | 3–4 班 |
| 4 | EC2 装好当执行机，先一个店对照跑一天，再整体切 | EC2 干活，Mac 只说话、开发、顶班 | 4–5 班 |

每一步开工前都先问您，照现在的上线流程走：开分支、对照、审查、合并。

## 7. 费用

- AWS 这几样基本在免费额度里：SQS、Lambda 每月 100 万次请求免费；DynamoDB 每月 25GB 存储加 25 个读写单位免费，我们的记录不到 1GB；按钮点击 16 天才 58 次。S3 单价开工前再核。
- 要花钱的是 EC2 升配置，以及业务变多以后的 AI 额度。
